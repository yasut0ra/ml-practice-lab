# モデルカード：用途・評価・限界を残す

[第27章](../exercises/ch27_monitoring.md) · [実験ノート](experiment-log.md) · [総合課題](capstone.md)

モデルを渡すとき、ファイルだけでは「何に使えるか」「どう確かめたか」が伝わりません。
モデルカードは、その判断に必要な情報を一か所に残す説明書です。
以下を自分のメモにコピーし、空欄を埋めます。まだ測っていない項目は「未評価」と書きます。

## コピーして使うひな形

| 項目 | 自分の記録 |
| --- | --- |
| 名前・バージョン・更新日・記録した人 | |
| 想定する用途と、予想する時点 | |
| この用途には使わない | |
| 入力の列・型・単位、予測の意味 | |
| データの由来・期間・件数・利用条件 | |
| 収集時に含まれない人や条件、個人情報の扱い | |
| 学習・設定選び・幅の調整・最終テストの分割 | |
| 時間や同じ人の重なりをどう扱ったか | |
| 前処理・モデル・設定・単純な基準 | |
| 選ぶ指標と、最後に報告する指標 | |
| 全体の結果・対象件数・正解が届いた件数 | |
| 部分集団の結果と、その件数 | |
| 未評価の条件・誤差が大きい例・結果の限界 | |
| 予測を受け取る人と、人が確認する手順 | |
| 入力や誤差を確認する周期・目安・担当 | |
| 答えの遅れや欠けをどう記録するか | |
| 変化が見つかったときの調査と、改良版の評価方法 | |
| 再現するコマンド・コード・環境・保存先 | |

項目の数より「他の人が読んで判断できるか」を優先します。
対象の一部だけで正解が届いた場合、その件数と届き方を書きます。
地域別のMAEが似ていても、それだけで公平性やすべての条件への適合性は証明できません。

## 第27章の記入例

以下は教材用の架空データの例です。実際の家賃予想サービスの説明書ではありません。
数値は実行環境で多少変わるため、自分で実行した値と環境を記録してください。

| 項目 | 記入例 |
| --- | --- |
| 名前・用途 | chapter27-rent-demo / 入力変化と誤差変化の違いを学ぶ |
| 用途の範囲 | 架空の部屋の月額家賃を万円で予想。実在物件の査定・契約判断には使わない |
| 入力 | 広さ㎡、駅までの分数、築年数、central/suburbの地域 |
| データ | コード内で生成。学習300件、基準120件、入力変化120件。関係変化は入力変化と同じ入力で答えに2.5万円を足した仮想比較 |
| モデル | 数値の空欄補完・標準化、地域の符号化、Ridge(alpha=1)。学習300件で固定 |
| 選び方 | この章では設定を固定して監視を練習。候補選択は行わず、選ぶ場合は別のCVと未使用の最終評価を用意 |
| 全体のMAE | 基準0.51万円、入力だけ変化0.49万円、関係も変化2.58万円。各120件、正解120件 |
| 関係変化の地域別 | central: 59件で約2.59万円、suburb: 61件で約2.56万円 |
| 正解が届く前 | MAEは未評価。入力の平均は確認できる。[解答](../answers/ch27_answer.py)で0件・40件・120件の正解到着を比較 |
| 確認の目安 | 説明用に、全体の平均広さが基準から10㎡を超えて変化／MAEが1.5万円を超えたら確認 |
| 変化への対応 | 入力・計測・正解の届き方を調べる。再学習する場合は新しい実験として別に評価する |
| 限界 | 120件の架空データの結果。基準との平均差だけでは分布全体の変化は測れない。現実の精度・原因・公平性を断定しない |

この例の目安は教材の説明用です。検知の誤警報率を統計的に保証するものではありません。
第27章の出力はモデル比較の最終テストではなく、固定したモデルを異なる条件で観察する表です。
モデルの設定をこの表から選んだら、その成績を新しい未使用データの評価として扱うことはできません。

## 再現する

macOS / Linuxは `.venv/bin/python scripts/ch27_monitoring.py`、
Windowsは `.venv\Scripts\python.exe scripts/ch27_monitoring.py` です。
結果は `outputs/monitoring_report.csv` に保存します。正解の遅れの例は `answers/ch27_answer.py` で実行できます。

第17章の[保存と環境の記録](../exercises/ch17_model_persistence.md)と組み合わせると、
前処理も含むモデル、入力の約束、説明書を一緒に渡せます。

モデルの想定用途・評価条件・限界を記録する考え方は
[Model Cards for Model Reporting（原論文）](https://arxiv.org/abs/1810.03993)を参照してください。
